Implement Principal Variation Search (PVS) in ShumiChess.

Make only the changes required to add PVS, its compile-time controls, and its statistics. Do not refactor, rename, reformat, optimize, or clean up unrelated code. Do not change aspiration search, transposition-table behavior, quiescence search, move ordering, evaluation, time control, abort handling, minimum depth, MultiPV behavior, or any other feature.

All modified files use CRLF line endings. Preserve CRLF line endings exactly.

1. Add PVS controls to `weights.hpp`

Place these with the other search-control constants near the top of `weights.hpp`:

```cpp
// Principal Variation Search controls.
inline constexpr bool PVS_ENABLED = true;
inline constexpr int PVS_MIN_DEPTH = 1;
```

`PVS_ENABLED` must completely enable or disable PVS.

When `PVS_ENABLED` is false, search behavior must follow the existing full-window path exactly.

`PVS_MIN_DEPTH` is the minimum remaining normal-search depth at which PVS may be used. Do not reinterpret this as iterative-deepening depth.

Do not add a tunable PVS window width. PVS must use a one-score-unit null window.

Use Shumi’s existing `Score` representation correctly. If one centipawn is one `Score` unit, use `1`. If an existing constant or conversion is required to represent one score unit, use that existing mechanism. Do not change the `Score` system.

2. Add game-wide PVS statistics

Add unsigned 64-bit counters alongside the existing search statistics:

```cpp
uint64_t pvs_attempts = 0;
uint64_t pvs_successes = 0;
uint64_t pvs_researches = 0;
uint64_t pvs_cutoffs = 0;
```

Meanings:

* `pvs_attempts`: completed narrow-window PVS searches.
* `pvs_successes`: narrow searches that did not require a full-window re-search.
* `pvs_researches`: narrow searches followed by a full-window re-search.
* `pvs_cutoffs`: narrow searches that returned a score greater than or equal to beta and therefore caused a cutoff without a full-window re-search.

Reset these counters at the same place where the existing game-wide aspiration statistics are reset. Do not change how or when the existing statistics are reset.

Do not count an interrupted or aborted narrow search as a completed PVS attempt.

3. Modify only the normal move-search portion of `loop_over_all_moves()`

`loop_over_all_moves()` is also used by quiescence search. PVS must never operate in quiescence.

A move qualifies for a PVS narrow search only when all of these are true:

```cpp
PVS_ENABLED
depth >= PVS_MIN_DEPTH
nSearched > 0
```

Also retain any existing condition necessary to distinguish normal search from quiescence. In Shumi, `depth > 0` identifies normal search, so the qualification must ensure that `depth > 0`.

The first searched move at every node must continue to receive the existing full-window search.

Every quiescence move must continue to receive the existing full-window search.

Do not change move ordering. PVS relies upon the first move already being ordered well.

4. Implement the PVS narrow search

For a qualifying move after the first searched move, search it first with the parent null window:

```text
[alpha, alpha + one score unit]
```

Because Shumi uses negamax, pass the corresponding negated child window:

```text
[-alpha - one score unit, -alpha]
```

Preserve the existing negation of the returned child score.

Use the current value of `alpha` that exists immediately before searching this move. If helpful for clarity and correctness, save it in a temporary variable such as:

```cpp
const Score pvs_alpha = alpha;
```

Do not alter `alpha` between the narrow search and the decision about whether a full-window re-search is needed.

Preserve every existing argument passed to the recursive search except for the alpha and beta arguments needed for the narrow window.

5. Decide whether to re-search

After a completed narrow search, increment:

```cpp
pvs_attempts++;
```

The narrow search is sufficient in either of these cases:

```cpp
score <= pvs_alpha
score >= beta
```

If:

```cpp
score >= beta
```

increment:

```cpp
pvs_cutoffs++;
pvs_successes++;
```

Then allow the existing beta-cutoff logic to process the result. Do not perform a full-window re-search.

If:

```cpp
score <= pvs_alpha
```

increment:

```cpp
pvs_successes++;
```

No full-window re-search is needed.

Only this case requires a full-window re-search:

```cpp
(score > pvs_alpha) && (score < beta)
```

For that case:

```cpp
pvs_researches++;
```

Then search the same move again using the exact full window that the old code used:

```text
[-beta, -pvs_alpha]
```

Preserve the existing negamax score conversion.

The result of the full-window re-search replaces the narrow-search result. All existing alpha updates, best-move handling, PV handling, TT storage, cutoff handling, and return handling must use the final result exactly as they did before PVS was added.

Do not perform a full-window re-search when the narrow result is already greater than or equal to beta. The narrow search has already proved the cutoff.

6. Preserve abort behavior

After the narrow search, use the same existing abort/stop handling that follows an ordinary recursive search.

If the narrow search was interrupted:

* Do not increment `pvs_attempts`.
* Do not increment any other PVS counter.
* Do not begin a full-window re-search.
* Follow the existing abort return path exactly.

After a full-window re-search, retain the existing abort handling exactly.

Do not add new timers, abort checks, or stop conditions.

7. Display the PVS summary in `playground()`

Display the counters in `playground()` beside the existing whole-game aspiration summary.

Calculate:

```cpp
const double pvs_success_pct =
    (pvs_attempts == 0)
        ? 0.0
        : 100.0 * (double)pvs_successes / (double)pvs_attempts;
```

Print a simple summary in this form:

```text
[PVS summary] success=95.2% attempts=123456 researches=5925 cutoffs=18420
```

Use the project’s existing output stream and formatting conventions. Do not introduce a new output mechanism.

When PVS is disabled, the counters should remain zero.

8. Required safeguards

Do not apply PVS:

* To the first searched move at a node.
* At `depth == 0`.
* Anywhere inside quiescence search.
* To a search that has already been aborted.
* By changing aspiration-window logic.
* By changing MultiPV logic.
* By changing TT flags, TT probing, TT replacement, or TT storage.
* By changing move sorting or move generation.

Do not change the existing meaning of `nSearched`.

Do not alter when `nSearched` is incremented.

Do not alter the existing full-window search expression except where necessary to select between the original full-window path and the new PVS path.
